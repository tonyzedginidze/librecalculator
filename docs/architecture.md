# Foundation architecture

> Mobile is parked: `apps/mobile` does not exist and the Expo/mobile notes below describe a deferred design. Do not build for it.

The Bun workspace contains `apps/web` (Astro), `apps/mobile` (Expo React Native), and `apps/desktop` (Vite React with Tauri), plus shared `calculators`, `content`, `i18n`, `design`, and `dom-ui` packages. Calculators own numeric parsing, pure domain contracts, engines, and their tests. Structured lessons belong in content; locale messages/formatting belong in i18n; design contains tokens and DOM styling. `dom-ui` shares web/desktop rendering primitives and exposes platform-independent interaction helpers separately; mobile has its own native views, not a universal component library. The percentage interface is implemented; installed-platform, offline, and release readiness are separate evidence gates recorded in the verification documents.

Each topic gets one `packages/calculators/src/<id>/` directory with a validated `metadata.json` marker, `index.ts` engine/descriptors, and colocated fixtures. Add matching `packages/content/src/<id>/index.ts` and `packages/i18n/src/topics/<id>.ts` files. `bun run generate` validates markers and required module existence, then emits metadata-only catalog/schema, plus literal lazy engine, lesson, and topic-message maps. Duplicate IDs/slugs, malformed markers, and missing modules fail generation; no source regex or executable metadata is used. `bun run check:generated` checks every generated output. Catalog/search imports only the lightweight UI labels in `i18n/src/en.ts`; it must not import engines, lessons, or topic prose. Selecting a topic explicitly invokes its corresponding lazy map. Native dynamic import may not reduce the shipped bundle, which must be inspected in Expo.

The generated core catalog currently contains all 10 initial calculator IDs and their validated input schemas: `area` (3 operations), `compound-interest` (1), `fractions` (5), `loan-payments` (1), `percentage` (2), `percentage-change` (1), `pythagorean` (2), `tip-splitting` (1), `unit-conversion` (1), and `volume` (3). `pythagorean` intentionally has the URL slug `pythagorean-theorem`. Engines, lesson modules, and topic-message maps are generated as sorted literal lazy imports; this core discovery does not imply that all topic UI views or full app integration are complete.

Platform runtime selection uses the generated `CalculatorId`. React-free adapters in `packages/dom-ui/src/topic.ts` provide the topic ID, schema version, operation descriptors, field parser, and typed calculation function. `evaluateDrafts<R, Code>` delegates parsing to the selected topic and preserves its result type; it does not impose decimal parsing or a shared visual/result schema. DOM topic views are independently discovered by the web/desktop Vite boundary. Mobile topic views use `apps/mobile/src/topics/<id>/view.tsx`; run `bun run generate:mobile-views` to produce the Metro literal-import map at `apps/mobile/src/topics/index.generated.ts`, or `bun run check:mobile-views` to verify it. The mobile generator checks the catalog only when explicitly run; general web/desktop builds do not require native view files.

The engine is pure, synchronous TypeScript. Inputs are canonical strings, results contain only serializable tagged numeric values, structured working, and topic-specific visual data with text alternatives. The shared contract contains only generic success/failure, numeric and working primitives; working arguments are tagged decimal/text/nested-message/reference values so renderers never guess whether a string needs numeric formatting. Error codes/result/visual schemas stay in each topic module. Each topic exports an operation-to-descriptor map, a typed `calculate(input)` entry point and its own visual type/renderer extension point. No translated prose, React, Intl, storage, or Decimal object crosses the engine boundary. Working and visual values derive from the same calculation output. Field descriptors support generic form rendering without a universal result/diagram schema. Draft text and caret state belong to each app. i18n renders working arguments from the generic contract, formats decimal arguments without Number conversion, resolves nested message/reference arguments, and validates template placeholders against operation descriptors.

The pure storage codec currently lives at `packages/calculators/src/runtime/local-state.ts`: this placement keeps versioned preferences/favorite/history contracts with calculator IDs and input schemas without mixing them into numeric engine code. It performs no I/O or engine import. It derives allowed IDs and operation/field schemas from generated catalog metadata and validates bounded string shape only; selected engines own numeric/domain validation when a history item is restored. This preserves future exact fraction inputs up to their documented limits. Preferences must validate as a whole, but unsupported/obsolete/malformed history entries and favorites are individually dropped and returned as indexed reports so adapters can explain what could not be restored; good entries remain. Payload size, history scan/count and field sizes (2048 characters per stored field) are bounded. Stored history contains canonical inputs, operation, units, timestamp and input-schema version, never a result snapshot. Codec dispatch is explicit by `version`; unsupported state versions are rejected rather than guessed.

Session mutations are asynchronous transactions exposed as `update(mutate): Promise<SessionSnapshot>` and `replaceSaved(): Promise<SessionSnapshot>`. The pure codec/save preparer remains shared, but each platform owns its serialization mechanism: browsers use the exclusive Web Lock named by `STORAGE_KEY` with no unlocked fallback, mobile queues every read/update/reset through one module-wide promise queue, and desktop uses a Rust mutex plus revisioned compare-and-set over an atomically replaced raw-state file. A failed save returns the previously persisted state with a notice; calculations remain immediate and local while persistence is pending. `saving-unavailable` and `save-conflict` notices are explicit UI states. Desktop's native file is authoritative after first initialization; valid prior browser storage is copied byte-for-byte only if the native store is empty, while invalid/unsupported legacy data stays write-blocked until the user explicitly resets.

## Packs

The ten initial calculators form the always-active `core` pack. `packs/<id>/pack.json` groups the existing topic-owned package folders without moving numeric engines or lesson modules. Generated `packs.generated.ts` contains metadata and membership only; missing, duplicate and unknown membership fail generation. Further calculators ship as activatable packs. The catalog stays in core and lists every calculator, while engines and lessons load only for active packs. Activation state is the only new persisted preference; saved history and favorites are out of scope for now. See [packs.md](packs.md) for design rules and phasing.

## Shared numerical contract

Canonical decimal inputs have optional sign, digits, and optional dot; no exponent/grouping is accepted by engines. `parseLocaleDecimal(raw, locale)` in i18n returns incomplete/invalid/valid without changing raw drafts, normalizes the locale decimal mark, and rejects grouping, whitespace, mixed/foreign separators and exponent notation. Draft text/caret remain app-owned. Limit numeric text to 256 characters, 30 significant digits and adjusted exponent magnitude 100. Decimal.js uses 50 significant digits. Reject non-finite and output exponent magnitude above 100. `formatDecimal` groups/localizes arbitrary-size exact decimal text without Number coercion or digit truncation; it uses exact decimal fallback for tiny values rather than silently formatting nonzero as zero. Exact fraction operations, when added, use bounded BigInt numerator/denominator and normalized rational results. Approximate roots, π, or powers must publish both absolute and relative fixture tolerance; default initial target is `abs(error) <= 1e-12` near zero and `rel(error) <= 1e-12` elsewhere (tighten where a stable exact fixture allows it). Tolerance never waives exact domain errors.

Package direction: calculators depend only on decimal.js internally; content owns schema-only lesson data; i18n owns messages, locale input/formatting; design owns tokens. i18n has a type-only source dependency on calculators' pure working contract; it emits no runtime calculators import. Platform app packages may depend on the shared packages; engines must not depend on apps, i18n, content renderers, or storage adapters. Declare any future runtime workspace dependency explicitly.

### Contracts for all ten initial calculators

| Topic | Domain and policy to preserve |
|---|---|
| Percentage | Signed values/rates, up to 30 significant digits and exponent ±100; rates above 100 allowed. A-as-%-of-B rejects B exactly zero. No intermediate rounding. |
| Percentage change | Signed old/new; old exactly nonzero. `(new-old)/old × 100`, including negative baseline; return actual delta and explain interpretation. |
| Fractions | Integer numerator/denominator with at most 1000 digits each; denominator nonzero; exact BigInt gcd reduction and sign normalization. Division by zero fraction rejected; negative mixed form puts sign outside positive whole/remainder. |
| Unit conversion | Explicit dimension-matched catalog; exact rational/decimal factors. Length: mm, cm, m, km, in, ft, yd, mi. Mass: mg, g, kg, oz, lb. Temperature: °C, °F, K via affine Kelvin transforms; reject below absolute zero. Area: mm², cm², m², km², in², ft², yd², acre, US survey acre only if explicitly supported. Volume distinguishes US liquid gallon/quart/pint/cup/fluid ounce from Imperial gallon/pint/fluid ounce; metric mL/L/m³. Time: ms, s, min, h, day, week. Calendar months/years and currencies excluded. Keep exact defining factors (e.g. inch 0.0254 m, international foot 0.3048 m, pound 0.45359237 kg, US gallon 3.785411784 L, Imperial gallon 4.54609 L) in a versioned unit catalog; never label US customary as Imperial. |
| Area | Positive dimensions. Rectangle, triangle using perpendicular base/height, circle. Square outputs; circle uses π approximation and labeled result. |
| Volume | Positive prism dimensions, cylinder radius/height, sphere radius. Cubic outputs; π-derived estimates labeled. |
| Pythagorean theorem | Positive lengths; exactly one missing side. Missing leg requires hypotenuse strictly greater than known leg by exact comparison. Root result approximate. |
| Compound interest | USD principal in whole cents; nominal annual rate 0–100%; positive integer years, maximum 1000; compounding per year 1, 2, 4, 12, or 365. `P(1+r/n)^(n·years)`. Round final balance/interest to cents, not every period; mathematical estimate, not settlement schedule. |
| Loan payments | USD principal whole cents; nominal annual rate 0–100%; positive integer term 1–1200 months; monthly schedule. Zero-rate branch. Round regular payment and each month's interest to cents, final payment clears balance; reject impossible cent schedules. Do not call input a fee-inclusive regulated APR. |
| Tip splitting | USD subtotal cents; tip 0–1000%; people 1–10000. Round total tip once to cents, split total cents into integer shares, allocate remainder cents to earliest shares and show that rule. Tip applies to entered subtotal only; no inferred tax. |

USD amounts are stored as integer cents and formatted as USD; translation/locale does not imply currency conversion. Settled money uses half-up cent rounding at the explicitly specified settlement boundary. Non-money values are not rounded during calculation. Financial exponentiation and approximate operations use 50-digit working precision and both absolute/relative fixture tolerances above; fixtures should cover near-zero and large magnitudes. These later-engine limits are contracts, not implemented engines in this phase.
