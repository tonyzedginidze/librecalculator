# Exact ratio and fraction contracts

These numerical policies are established before the percentage-change and fraction engines. Both are pure arithmetic with canonical text inputs; localization, grouping, and formatting stay at the platform boundary. Neither engine converts values through JavaScript `Number`.

## Percentage change

- Inputs are signed finite canonical decimals parsed with the existing decimal utility: at most 256 characters and 30 significant digits, no grouping or exponent notation, and adjusted input/output exponent magnitude at most 100. Arithmetic uses the existing 50-significant-digit Decimal clone and does not round intermediate values.
- The old value is the signed baseline and must be nonzero. The exact delta is `new − old`; percentage change is `(new − old) / old × 100`. The engine returns both the delta and the percentage change. A zero old value is undefined and is rejected, including when the new value is also zero.
- Negative baselines are not replaced by their absolute value. For example, moving from `−100` to `−50` has delta `+50` but percentage change `−50%`. A positive change percentage with a negative baseline does not necessarily mean the new value is larger: `−100` to `−150` has delta `−50` and percentage change `+50%`. Results are mathematical signed comparisons, not claims about financial gain/loss.
- Results outside the existing decimal output exponent bound fail explicitly. Zero signs are normalized by Decimal arithmetic.

## Fractions

- Numerator and denominator inputs are base-10 signed integers with optional leading `+`/`−`; no decimal point, grouping, whitespace, or exponent notation. Each magnitude may contain at most 1000 digits (including leading zeros); total text length is capped at 1001 characters including an optional sign. Denominators cannot be zero. Empty or malformed components and over-limit integers are rejected with a field-specific failure.
- Each input and result is normalized by greatest common divisor: denominator positive, numerator/denominator coprime, and zero represented as `0/1`. A zero denominator is invalid. Division by a fraction whose numerator is zero is invalid.
- The exact result is always the primary output as signed `numerator/denominator`; integers are represented with denominator 1. Addition, subtraction, multiplication, division, and reduction use `bigint` only. Multiplication/division cancel common factors before products; addition/subtraction use denominator GCD scaling. No approximation or decimal rounding is performed.
- Normalized output numerator and denominator magnitudes are each bounded to 2001 decimal digits. This accommodates the largest possible cross-product sum of two 1000-digit input fractions, while keeping output sizes explicit. Any result exceeding the bound fails; it is never truncated. Inputs are capped before BigInt construction. Intermediate work is bounded by the declared input/output sizes and uses Euclidean GCD.
- Mixed display is derived from the same normalized rational. The sign is outside a positive whole part and positive remainder: `−7/3` displays as `−2 1/3`; proper fractions display with whole part zero; exact integers have remainder zero. The exact `n/d` remains primary.
- The visual carries the exact normalized rational, proper remainder, and mixed form. Its number line is explicitly bounded to `−10` through `10`; the exact marker value is never clamped. Values outside that window are marked outside with their exact value still shown. Negative values retain their sign. Portion/equivalence display is derived from the normalized result, not a separate approximation.

## Independent reference fixtures

Expected results are authored by hand and checked as exact normalized integer strings, not generated by the engine under test:

| Operation | Inputs | Exact expected result |
|---|---|---|
| Add | `1/2 + 1/3` | `5/6` |
| Subtract | `1/2 − 3/4` | `−1/4`; mixed `−1/4` |
| Multiply | `2/3 × 9/4` | `3/2`; mixed `1 1/2` |
| Divide | `(2/3) ÷ (4/5)` | `5/6` |
| Reduce | `−42/−56` | `3/4` |
| Mixed display | `−7/3` | `−2 1/3` |
| Large cancellation | `(10^999)/(3 × 10^999)` | `1/3`, using separately authored 1000-digit numerator/denominator text |
| Percentage change | `100 → 125` | delta `25`, change `25%` |
| Negative baseline | `−100 → −50` | delta `50`, change `−50%`, negative-baseline interpretation flag true |
| Negative baseline | `−100 → −150` | delta `−50`, change `50%`, negative-baseline interpretation flag true |
| Full decline | `50 → 0` | delta `−50`, change `−100%` |

Boundary tests additionally cover zero denominator/baseline/divisor, malformed and oversized integers, signs, zero normalization, output limits, and values around the number-line window. All percentage-change reference outputs are exact terminating decimals and checked exactly.
