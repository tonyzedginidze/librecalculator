# Unit-conversion numerical contract

## Domain and catalog

The engine accepts signed finite decimal input with the shared canonical-decimal constraints: up to 30 significant digits, no grouping or exponent notation, and a supported adjusted exponent of at most 100. Results use the shared 50-significant-digit Decimal context and are not rounded for display in intermediate calculations. Output outside the shared exponent range is rejected. `value` is decimal input; `source` and `target` are canonical catalog IDs and are persisted as ordinary string fields.

Supported dimensions are length, mass, temperature, area, volume, and elapsed time. A conversion is only defined within one dimension. Currency is excluded. Weeks are exactly seven days; months and years are not offered because they are not fixed elapsed durations.

| Dimension | Units and SI base factor |
|---|---|
| Length (m) | mm 0.001; cm 0.01; m 1; km 1000; in 0.0254; ft 0.3048; yd 0.9144; mi 1609.344 |
| Mass (kg) | mg 0.000001; g 0.001; kg 1; avoirdupois oz 0.028349523125; lb 0.45359237 |
| Area (m²) | mm² 0.000001; cm² 0.0001; m² 1; km² 1000000; in² 0.00064516; ft² 0.09290304; acre 4046.8564224; hectare 10000 |
| Volume (m³) | mL 0.000001; L 0.001; m³ 1; US fl oz 0.0000295735295625; US cup 0.0002365882365; US pint 0.000473176473; US quart 0.000946352946; US gallon 0.003785411784; Imperial fl oz 0.0000284130625; Imperial pint 0.00056826125; Imperial gallon 0.00454609 |
| Time (s) | ms 0.001; s 1; min 60; h 3600; day 86400; week 604800 |

Linear conversion is `x × sourceFactor ÷ targetFactor`. The decimal factors encode exact definitions (including 1 in = 0.0254 m, 1 lb = 0.45359237 kg, 1 US gallon = 0.003785411784 m³, 1 Imperial gallon = 0.00454609 m³, and 1 acre = 4046.8564224 m²). The US fluid ounce is US gallon/128, US cup US gallon/16, US pint US gallon/8, US quart US gallon/4, and Imperial fluid ounce Imperial gallon/160. Division that has a repeating decimal is evaluated with 50 significant digits. Fixture comparisons use absolute tolerance `1e-12 + 1e-12 × |reference|`.

## Temperature and failure behavior

Temperature uses exact decimal affine transformations through Kelvin: `K = C + 273.15`, `K = (F − 32) × 5/9 + 273.15`; reverse transforms are `C = K − 273.15` and `F = (K − 273.15) × 9/5 + 32`. Values below 0 K are rejected by an exact sign check with no tolerance (`C < -273.15` and `F < -459.67` consequently fail). Negative readings above absolute zero are valid. Identity conversions preserve canonical values.

Malformed decimals or unknown IDs return `invalid-field` (field set when identifiable); dimension mismatches return `incompatible-units`; below-absolute-zero temperatures return `below-absolute-zero`; out-of-range answers return `output-overflow`. No currency or calendar arithmetic is implied.

## Choice-field contract and platform handoff

Choice descriptors contain stable `{id, labelKey}` choices, and their default must be one of those IDs. The content validator verifies uniqueness/identifier syntax, translated labels, and defaults. Only the IDs enter the existing domain-neutral string input/history records; no duplicate unit state is stored. Topic parsing must validate choice IDs and return the canonical ID instead of forcing decimal parsing. UI rendering is owned by platform integration; this numerical/content lane does not change UI components. The designer/controller lane must consume the `choice` input type and persist/restore `source` and `target` IDs. Until then, existing decimal-only consumers require integration work; no fallback is claimed.

## Independent fixtures and references

Fixtures include 1 in = 0.0254 m, 1 lb = 0.45359237 kg, US gallon = 3.785411784 L, Imperial gallon = 4.54609 L, 0 °C = 32 °F = 273.15 K, 0 K = −273.15 °C = −459.67 °F, 1 acre = 4046.8564224 m², and 1 day = 86400 s. They also cover negative linear values, identity, reverse conversion, high magnitude, incompatible dimensions, and below-absolute-zero rejection. Expected fixtures are authored from the definitions and are not generated by the engine.

References: [NIST SI units](https://www.nist.gov/pml/owm/metric-si/si-units) and [NIST SP 811](https://www.nist.gov/pml/special-publication-811).

## Units launch presets

The length, mass, temperature, duration, speed-conversion and cooking-measures calculators are data-driven presets over a core unit catalog and pure conversion primitive in `numeric/`. They never import another pack's calculator. The original unit-conversion engine uses the same primitive and retains its original six dimensions/choices. Every preset restricts source and target IDs to its own supported dimension; invalid or external choices fail explicitly. Signed linear quantities are permitted; absolute-temperature readings are not allowed below zero Kelvin. Exact source-scale absolute-zero comparison precedes affine arithmetic, including identity conversions.

Speed factors preserve rational denominators: m/s is base 1; km/h is 1000/3600; mph is 1609.344/3600; ft/s is 0.3048; knots are 1852/3600. A knot uses the international nautical mile. Convert with `value × sourceNumerator × targetDenominator ÷ targetNumerator ÷ sourceDenominator` at shared 50-significant-digit precision. No rounded repeating factor is stored. Examples: 36 km/h=10 m/s; 60 mph=96.56064 km/h; 1 knot=1.852 km/h.

Cooking volumes extend the explicit US liquid and Imperial catalog with metric cup=250 mL, metric teaspoon=5 mL, metric tablespoon=15 mL and Australian tablespoon=20 mL. These labels are definitions of the selected preset, not claims that every recipe uses them. Do not infer ingredient mass. Fixtures: US customary cup=236.5882365 mL; metric cup=250 mL; Australian tablespoon=20 mL.

Each preset has three independently authored exact fixtures, choice-validation tests and topic-owned lessons with unit-specific mistakes and assumptions. Length excludes the former US survey foot; mass uses avoirdupois ounces rather than troy/fluid ounces; duration uses fixed 86400-second days rather than civil calendar days. Shared canonical numeric and overflow bounds remain unchanged.
